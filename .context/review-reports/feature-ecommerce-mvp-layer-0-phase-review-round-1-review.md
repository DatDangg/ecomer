# Phase Review — ecommerce-mvp / Layer 0 / round 1

## Verdict

⚠️ **GAPS FOUND** — Most Layer 0 foundations are implemented and the six task-level review reports are PASS. However, the backend JWT strategy/configuration is not registered in a runtime Nest module, so protected L1 routes cannot yet use the delivered strategy/guards as-is. The global throttle also executes before route guards, contrary to the documented guard order. As-built docs still claim there is no application code. These are limited foundation/integration gaps; the business APIs themselves remain validly planned for L1.

- The latest task review reports are PASS: task-01 round 3, task-02 round 2, task-03 round 2, task-04 round 3, task-05 round 2, task-06 round 4 (paths listed in the matrix).
- No configured verification command was rerun for this phase review. Tests/build claims below are attributed to the task-level reports; live MongoDB startup and browser-rendered checks were not independently verified.

## Gaps

1. **[PARTIAL] Runtime JWT foundation is not wired** — requirement/source: R-01 identity foundation and task-04 acceptance (“JwtModule configured” and guards/strategy usable); related task: `tasks/ecommerce-mvp/layer-0-task-04.md`. The helper/strategy source is tested but no runtime module registers Passport/JWT or provides `JwtStrategy`. Before protected auth/user/shop/admin routes rely on it, register the strategy/module configuration and verify boot/guard integration. This is the primary L1 unlock blocker for protected endpoints.
2. **[PARTIAL] Documented guard execution order differs from actual Nest wiring** — requirement/source: `SPECIFICATIONS.md:182`, `docs/ARCHITECTURE.md:124-130`, `docs/PERMISSION.md:19-29`; related task: task-01 (global throttling) and task-04 (route guards). `ThrottlerGuard` is the only global guard today and runs before route-level guards; ownership checks are service-level. Reconcile the claimed order with actual sequencing as L1 guards/routes are wired. This is a contract/docs alignment issue; rate limiting currently applies globally at the throttle module's configured limit.
3. **[PARTIAL] As-built docs still describe a code-empty repository** — requirement/source: API/ERD/architecture source-of-truth declarations; docs: `docs/ARCHITECTURE.md:217`, `docs/API_SPEC.md:8-12`, `docs/ERD.md:8-11`; related task: `tasks/ecommerce-mvp/layer-0-task-03.md` (repo documentation foundation). Update those current-state claims/pointers in the layer close-out; do not change intent requirements to match implementation.

No additional L0 business/data requirement is marked MISSING. Differences in unimplemented Auth/User/Shop/Category endpoint behavior are excluded as planned L1 scope.

## L1 unlock assessment

**Not fully clear for protected L1 API implementation without a foundation correction.** Public Category API work can begin independently. Auth endpoints and protected User/Shop/Admin endpoints must first wire the JWT strategy/configuration and establish the actual guard usage/order. This can be a small prerequisite at the start of L1; it does not require prematurely implementing the deferred business endpoints in Layer 0. Once wired, the response envelope, pagination, DB topology, ownership primitives, and FE data layer provide the expected foundation.

## Deferred (valid L1+ scope; not counted as Layer 0 gaps)

- **L1 auth APIs:** registration/login/refresh/logout, token issuance and refresh-hash lifecycle, endpoint-specific auth throttling at 10 requests/minute/IP.
- **L1 user/shop APIs:** `GET/PATCH /users/me`, shop setup and public shop lookup.
- **L1 category APIs:** category schema and public/admin CRUD, including unique-name/slug behavior and product-aware delete guard.
- Product and upload APIs (R-04/R-05/R-13); cart (R-06); checkout/order/transaction business flows (R-07/R-09/R-10); VNPay payment/callback/expiry logic (R-08); admin management APIs (R-11); go-live/deploy/smoke tests (R-12).

These endpoints/business behaviors are not implemented in L0, as expected. Replica-set startup verification is a prerequisite, not evidence that checkout transactions themselves have been implemented.
